# ChatGPT 登入、內部授權與店家邀請

部署到 ChatGPT Sites 後，Worker 僅信任平台在伺服器端加入的 `oai-authenticated-user-id`、email 與名稱標頭；前端送來的角色、Cookie 或自訂 header 都不會影響權限。

## 部署前設定

在 Sites 的 server-side environment variables 設定下列逗號分隔清單（範例見 [`.env.example`](../.env.example)）：

- `LUNCH_ADMIN_IDS`：平台管理員的穩定 ChatGPT 使用者 ID。
- `LUNCH_MEMBER_IDS`：可進入團購與小鎮的內部成員 ID。

管理員也自動是內部成員。兩個清單預設都是空的，代表 fail closed：登入本身不會取得團購權限。更新清單後，下一個請求立即以新設定判斷，沒有「第一位登入者自動成為管理員」的規則。

使用者登入後若尚未具備內部權限，畫面會顯示自己的 opaque ID，供管理員加入清單。此 ID 是此 Site 的帳號識別，請不要改用 email 當作授權鍵。

## 權限模型

| 身分 | 可以做什麼 |
| --- | --- |
| 未登入 | 只能看到登入入口與邀請連結畫面。 |
| 內部成員 | 建團、加入、點餐、讀取小鎮。 |
| 平台管理員 | 內部成員權限，加上開店、建立／撤銷店家邀請。 |
| 店家管理者 | 只可管理受邀店家；不能讀取團購或小鎮。 |

店家管理權是獨立於內部成員的資料。平台管理員不會因管理員身分自動取得任何一家店的後台；開店者或接受特定店家邀請的人才是該店管理者。

## 邀請店家

1. 管理員登入後，從頂欄開啟「管理店家邀請」。
2. 店家先使用 ChatGPT 登入，將畫面上的使用者 ID 提供給管理員。
3. 管理員選店家、貼上 ID，建立一次性邀請連結（預設 7 天，可選 1–30 天）。
4. 連結只在建立當下顯示一次；token 在資料庫只保存 SHA-256 雜湊。
5. 目標帳號開啟連結並接受後，才取得該店後台。管理員可在邀請紀錄撤銷尚未使用的連結，也可撤銷既有店家管理者。

## 開發模式與限制

`npm run dev` 的 Fastify／Socket.IO 本機模式保留舊有匿名 cookie 與展示管理碼，方便既有測試與本機操作；它不是 Sites 的授權驗證環境。正式 Sites 流程不讀取 `lt_sid` Cookie，也禁止管理碼認領。

目前 allowlist 以 Sites 的 server-side environment variables 管理，適合黑客松與小型內部平台。若日後需要自助加入、群組同步或審計歷程，應把成員資料改為受控資料庫／組織目錄，並保留同一個 server-side authorization boundary。
